# Warehouse Module — Enhancement Plan

> **Scope:** `resources/views/pages/products/warehouse/` · `app/Http/Controllers/Product/Warehouse/` · related models & routes  
> **Date:** 2026-04-16  
> **Priority key:** 🔴 High · 🟡 Medium · 🟢 Low

---

## 1. Barcode Module

### 🔴 Missing Filters on Barcode List
The index query only filters by search, date range, and per-page. Add:
- **Status filter** (`active` / `used`) — dropdown in the filter bar
- **Category filter** — dropdown populated from `ProductCategory`
- **Container ID filter** — separate exact-match input (currently merged into search)

**Controller change — `BarcodeController@index`:**
```php
->when($request->filled('status'),      fn($q) => $q->where('status', $request->status))
->when($request->filled('category_id'), fn($q) => $q->where('category_id', $request->category_id))
```
Add matching `<select>` fields to the filter bar in `barcode/index.blade.php`.

---

### 🔴 Barcode Batch History Page
`barcode_batches` table is populated on every generate call but never shown in the UI.  
Add a **Batch History** tab/section in `barcode/index.blade.php` listing:
- Batch number · Container ID · Category · Range (start → end) · Qty · Generated by · Date
- Click-through to filter the main table to that batch

**Route to add:**
```
GET /product/warehouse/barcode/batches → BarcodeController@batches
```

---

### 🟡 Barcode Status Badge in Print View
`barcode/print.blade.php` renders QR codes but does not show the `status` (active/used) visually.  
Print the status as a small coloured label under each QR so physical scanners can identify used barcodes.

---

### 🟡 Bulk Mark-as-Used (UI)
`BarcodeController@bulkMarkAsUsed` exists and works but the UI button is commented out in `index.blade.php` (lines 118–125).  
Uncomment and wire it back up; the backend logic is already correct.

---

### 🟢 Barcode Image Regeneration
If a barcode PNG is accidentally deleted from storage, there is no way to regenerate it without deleting and re-creating the record.  
Add a **Regenerate Image** action per row that calls `generateBarcodeImage()` privately and saves the new path.

---

## 2. Product Module

### 🔴 Summary Stats Bar Above Product List
`products/index.blade.php` has no at-a-glance count strip.  
Add a stats row (similar to the dashboard) showing:
- Total products in current filter view
- Active / Inactive breakdown
- Sold / Scrapped counts

Pass these as compact counts from `ProductController@index` without a separate AJAX call.

---

### 🔴 Product Timeline History UI
`products/history.blade.php` exists but renders a plain table.  
Replace with a vertical timeline component showing:
- Icon per action type (location move, inspection, stage change, sale, scrap)
- Actor avatar/name
- Old → New value comparison with colour diff
- Relative timestamps ("2 hours ago")

No backend change needed — `ProductHistory` model already stores everything required.

---

### 🟡 Advanced Filter: Assigned / Unassigned Toggle
`ProductController@index` supports filtering by `assigned_to` but there is no quick **"Unassigned only"** toggle.  
Add a checkbox or quick-filter pill that appends `?unassigned=1` and adds `.whereNull('assigned_to')` in the scope.

---

### 🟡 Duplicate Product Detection
When creating or importing a product, the system does not warn about similar `unique_id` or `title` values within the same company.  
Add a live AJAX uniqueness check on the `unique_id` field in `products/create.blade.php`.

---

### 🟢 Product Import via CSV / Excel
Currently products are created one by one or via barcode generation.  
Add a CSV import route (`POST /warehouse/products/import`) that reads columns:
`unique_id, title, category_id, location_id, disposition_id, status, specifications_json`

Use `laravel-excel` (`maatwebsite/excel`) which is already available for exports.

---

## 3. Parts / Inventory Module

### 🔴 Low Stock Email / In-App Notification
`Part::isLowStock()` and `Part::needsReorder()` methods exist but no notification is triggered when stock drops below `min_stock_level`.  
Create a scheduled job (`app/Console/Commands/CheckLowStock.php`) running daily:
```php
Part::lowStock()->forCompany($companyId)->each(fn($p) => Notification::send(...));
```
Show the alert count as a badge on the sidebar Parts menu item.

---

### 🔴 Part Movement History Page
`PartMovement` model and `PartsController@movements` route exist but there is no blade view for it.  
Create `parts/movements.blade.php` with a filterable table:
- Date · Type (IN / OUT / TRANSFER) · Qty · Before → After · Reason · Actor

---

### 🟡 Reorder Request Workflow
Parts at or below `reorder_level` should generate a **Purchase Request**.  
Add a simple `purchase_requests` table (part_id, requested_qty, status, requested_by) and a form accessible from the part detail page.

---

### 🟡 Supplier Information on Parts
`parts` table has no supplier fields.  
Add migration:
```
supplier_name, supplier_contact, supplier_lead_days
```
Display on `parts/detail.blade.php` and allow editing in `parts/edit.blade.php`.

---

### 🟢 Part Stock Adjustment
There is no direct "adjust stock" action for corrections (e.g., after a physical count).  
Add a modal on `parts/index.blade.php` with `reason` and `new_quantity` fields, creating a `ADJUSTMENT` PartMovement record.

## 9. Database / Performance

### 🔴 Missing Indexes
The following columns are used in `WHERE` and `ORDER BY` but likely lack indexes:

| Table | Column |
|---|---|
| `products` | `disposition_id`, `work_flow_stage_id`, `assigned_to`, `company_id` |
| `barcodes` | `status`, `category_id`, `container_id`, `company_id` |
| `parts` | `status`, `warehouse_location_id`, `company_id` |
| `product_assignments` | `technician_id`, `completed_at`, `due_date` |
| `product_history` | `product_id`, `field`, `changed_by` |
| `gate_pass_items` | `gate_pass_id`, `product_id` |

Add via migration:
```php
Schema::table('products', function (Blueprint $table) {
    $table->index(['company_id', 'disposition_id']);
    $table->index(['company_id', 'work_flow_stage_id']);
});
```

---

### 🔴 N+1 Queries on Product List
`products/index.blade.php` loops over products and accesses `$product->category`, `$product->warehouseLocation`, `$product->disposition`, `$product->workflowStage`, `$product->assignedTo`.  
Ensure `ProductController@index` eager-loads all five:
```php
Product::with(['category','warehouseLocation','disposition','workflowStage','assignedTo'])
```
Check this is consistent — missing `with()` causes N+1.

---

### 🟡 Barcode Image Storage Cleanup
Deleted barcodes leave orphaned PNG files in `storage/public/barcodes/`.  
In `BarcodeController@destroy` and `@bulkDelete`, call `Storage::delete($barcode->barcode_image_path)` **before** the model is deleted (already partially handled — verify bulk path).

---

### 🟡 Cache Dashboard Stats
`DashboardController@index` runs multiple heavy aggregation queries on every page load.  
Cache the result for 5 minutes:
```php
$stats = Cache::remember("dashboard_stats_{$companyId}", 300, fn() => $this->buildStats($request));
```
Clear the cache on key write operations (product status change, assignment complete, etc.).

---

## 10. Code Quality / Consistency

### 🟡 Route Naming Inconsistency
Some routes use prefix `product.warehouse.*` and others use `warehouse.*` without the `product.` prefix.

---

### 🟡 Response Format Inconsistency
Some AJAX endpoints return `{'success': true, 'message': '...'}` and others return `{'status': 'ok'}`.

---

### 🟢 Extract Shared Blade Components
Several modules (products, parts, gate passes, scrap) duplicate the same filter-bar markup, bulk-action toolbar, and export dropdown.  
Extract to Blade components:
- `<x-warehouse.filter-bar :action="..." />`

Several index/show blades have `<script>` blocks embedded inside `@section('content')` instead of the dedicated `@push('scripts')` stack.  
Move all JavaScript to the scripts stack for cleaner HTML structure.
